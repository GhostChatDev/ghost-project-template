# Project-specific lessons

Record useful lessons only after observing an implementation or review. Keep the scope and evidence; do not turn one project's result into a universal visual style.

## Motion references are not dependencies

Lesson: A list of fifteen motion repositories initially sounded like a library stack to install. That would impose technology before the project's audience, platform, and visual direction were defined.

Rule: Keep references opt-in and documentation-only. For each one, record its role, platform fit, license, example or entry points, and inspection date. Read source for techniques; compare native platform APIs before importing anything. Do not copy implementation code, add a package, or vendor an asset without confirming the project's requirements and the source's license.

Applies to: web, game, iOS, Android, video
